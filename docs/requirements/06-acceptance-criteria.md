# 06. Критерии приёмки (AC)

Формат: Given / When / Then. Трассировка к UC и FR: [05-use-cases](05-use-cases.md), [03-functional-requirements](03-functional-requirements.md).

## AC-1 (UC-1; FR-1, FR-2, FR-13)

- **Given** кандидат без приглашения или одобрения, **When** открывает Mini App, **Then** видит форму заявки, анкета недоступна.
- **Given** одобренный кандидат, **When** завершает онбординг без имени, без навыков или без явного выбора формата встречи, **Then** сохранение заблокировано, поля подсвечены.
- **Given** корректно заполненная анкета, **When** онбординг завершён, **Then** анкета сохранена, кандидат становится участником и видит колоду карточек.

## AC-2 (UC-2; FR-3, FR-4)

- **Given** участник, **When** меняет навык и сохраняет, **Then** новый навык находится поиском (FR-10) не позднее чем через 1 мин.
- **Given** участник, **When** пытается сохранить анкету с пустым именем или без навыков, **Then** сохранение заблокировано, поля подсвечены (FR-3).
- **Given** участник, **When** сохраняет имя длиной 1 или 65 символов, **Then** сохранение отклонено с сообщением о границах поля (2–64 символа).

## AC-3 (UC-3; FR-5, FR-6, FR-9)

- **Given** участник оценил карточку, **When** колода обновляется, **Then** эта карточка больше не показывается.
- **Given** все рекомендации исчерпаны, **Then** показывается заглушка «карточки закончились; новые появятся с новыми участниками», ошибок нет.
- **Given** участник оценил карточку, **When** находит того же участника в поиске, **Then** карточка показывается с меткой текущей оценки (FR-9, FR-12).

## AC-4 (UC-4; FR-7, FR-8, FR-14, NFR-12)

- **Given** участник A оценил B «интересно», а B не оценил A, **Then** контакт A не раскрыт B.
- **Given** взаимные оценки «интересно», **When** проходит ≤ 1 мин, **Then** оба получили от бота сообщение с Telegram-контактом друг друга (приёмка — после закрытия Q10).
- **Given** матч создан, **When** участник повторно открывает раздел «Матчи» в Mini App, **Then** контакт второй стороны доступен (FR-8).

## AC-5 (UC-5; FR-10, FR-11, FR-12, NFR-2)

- **Given** 100 анкет, из них 10 с тегом `Kafka` (алиасы `kafka`, `Кафка`) и 90 без него, **When** запрос «разобраться с кафкой», **Then** первые 10 результатов — анкеты с тегом `Kafka`, и они идут выше анкет без тега; ответ ≤ 5 с (NFR-2).
- **Given** анкета с проектом, содержащим слово «миграция», **When** запрос «миграция», **Then** анкета присутствует в результатах (поиск по проектам, FR-10).
- **Given** анкета с профессиональным интересом «Kafka» и анкета с навыком «Kafka», **When** запрос «кафка», **Then** анкета с навыком выше анкеты с интересом (приоритет полей, FR-10).
- **Given** результаты поиска, **When** применён фильтр «offline + Москва», **Then** остаются только анкеты с локацией Москва и форматом offline/any (FR-11).
- **Given** карточка из поиска получила взаимную оценку «интересно», **Then** срабатывает UC-4.

## AC-6 (UC-6; FR-13, FR-15, NFR-7, NFR-9, NFR-12)

- **Given** запрос к API без валидного Telegram `initData`, **When** запрос выполняется, **Then** ответ 401.
- **Given** не-модератор вызывает функцию управления допуском (FR-15), **When** запрос выполняется, **Then** ответ 403.
- **Given** заявка кандидата, **When** модератор одобряет её, **Then** кандидат получает уведомление бота ≤ 1 мин (NFR-12) и доступ к онбордингу (UC-1).
- **Given** заявка кандидата, **When** модератор отклоняет её, **Then** кандидат получает уведомление бота, онбординг недоступен, повторная подача разрешена.

## AC-7 (нефункциональные требования; NFR-1, NFR-3…NFR-6, NFR-8, NFR-10, NFR-11)

- **NFR-1.** **Given** устройство с сетью 4G, **When** участник открывает Mini App, **Then** первичная загрузка завершается ≤ 3 с (замер на реальном устройстве, p95 по 10 запускам).
- **NFR-3.** **Given** участник в колоде карточек, **When** он оценивает карточку, **Then** следующая карточка отрисована ≤ 1 с в p95.
- **NFR-4.** **Given** нагрузочный тест 50 одновременных сессий на базе 1 000 анкет, **When** выполняются основные операции (колода, оценка карточки, поиск), **Then** ответы API укладываются в NFR-2/NFR-3, ошибок 5xx < 1%.
- **NFR-5.** **Given** участник, **When** он пытается добавить 31-й навык, 21-й проект или 31-й интерес, **Then** система отклоняет ввод с понятным сообщением о лимите.
- **NFR-6.** **Given** эксплуатация за месяц, **Then** суммарное время недоступности ≤ 0,72 ч (доступность ≥ 99%).
- **NFR-8.** **Given** участник без матча с X, **When** он запрашивает карточку X через API, **Then** ответ не содержит ни username, ни user id X, ни скрытых до матча полей (`last_name`, `personal_interests` — FR-14); проверка сырого ответа API.
- **NFR-10.** **Given** выбранная юрисдикция (ответ на Q3), **Then** есть задокументированные: место хранения ПДн, политика хранения и процедура удаления анкеты по запросу участника.
- **NFR-11.** **Given** актуальные клиенты Telegram на iOS, Android и Desktop, **When** участник проходит UC-1…UC-5, **Then** все сценарии работоспособны на каждой платформе (ручной чек-лист).
