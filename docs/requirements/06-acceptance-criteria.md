# 06. Критерии приёмки (AC)

Формат: Given / When / Then. Трассировка к UC и FR: [05-use-cases](05-use-cases.md), [03-functional-requirements](03-functional-requirements.md).

## AC-1 (UC-1; FR-1, FR-2, FR-13)

- **Given** пользователь без доступа, **When** открывает Mini App, **Then** видит форму заявки, анкета недоступна.
- **Given** одобренный пользователь, **When** завершает онбординг без имени или без навыков, **Then** сохранение заблокировано, поля подсвечены.
- **Given** корректно заполненная анкета, **When** онбординг завершён, **Then** анкета сохранена и участник видит ленту рекомендаций.

## AC-2 (UC-2; FR-3, FR-4)

- **Given** участник, **When** меняет навык и сохраняет, **Then** новый навык находится поиском (FR-10) не позднее чем через 1 мин.

## AC-3 (UC-3; FR-5, FR-6, FR-9)

- **Given** участник оценил карточку, **When** лента обновляется, **Then** эта карточка больше не показывается.
- **Given** все рекомендации исчерпаны, **Then** показывается заглушка, ошибок нет.

## AC-4 (UC-4; FR-7, FR-8, FR-14, NFR-12)

- **Given** участник A лайкнул B, а B не лайкал A, **Then** контакт A не раскрыт B.
- **Given** взаимные лайки, **When** проходит ≤ 1 мин, **Then** оба получили от бота сообщение с Telegram-контактом друг друга.

## AC-5 (UC-5; FR-10, FR-11, FR-12, NFR-2)

- **Given** 100 анкет с навыком «Kafka», **When** запрос «разобраться с кафкой», **Then** в топ-10 результатов есть анкеты с навыками Kafka/Кафка; ответ ≤ 5 с.
- **Given** результаты поиска, **When** применён фильтр «offline + Москва», **Then** остаются только анкеты с локацией Москва и форматом offline/any.
- **Given** карточка из поиска лайкнута взаимно, **Then** срабатывает UC-4.

## AC-6 (UC-6; FR-13, NFR-7, NFR-9)

- **Given** запрос к API без валидного Telegram `initData`, **Then** ответ 401.
- **Given** не-модератор вызывает модераторскую функцию, **Then** ответ 403.
