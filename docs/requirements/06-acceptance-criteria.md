# 06. Критерии приёмки (AC)

Формат: Given / When / Then. Трассировка к UC и FR: [05-use-cases](05-use-cases.md), [03-functional-requirements](03-functional-requirements.md).

## AC-1 (UC-1; FR-1, FR-2, FR-13, FR-16)

- **Given** кандидат без приглашения или одобрения, **When** открывает Mini App, **Then** видит форму заявки, анкета недоступна.
- **Given** одобренный кандидат, **When** завершает онбординг без имени, без навыков или без явного выбора формата встречи, **Then** сохранение заблокировано, поля подсвечены.
- **Given** корректно заполненная анкета, **When** онбординг завершён, **Then** анкета сохранена, кандидат становится участником и видит колоду карточек.
- **Given** кандидат не подтвердил согласие (FR-16), **When** пытается завершить онбординг, **Then** завершение заблокировано, показан текст согласия.

## AC-2 (UC-2; FR-3, FR-4)

- **Given** участник, **When** меняет навык и сохраняет, **Then** новый навык находится поиском не позднее чем через 1 мин (FR-3).
- **Given** участник изменил анкету, **When** прошло ≤ 1 мин, **Then** его карточка в колоде других участников содержит новые значения (FR-3).
- **Given** участник, **When** пытается сохранить анкету с пустым именем или без навыков, **Then** сохранение заблокировано, поля подсвечены (FR-3).
- **Given** участник, **When** сохраняет имя длиной 1 или 65 символов, **Then** сохранение отклонено с сообщением о границах поля (2–64 символа).
- **Given** участник редактирует навыки, **When** набирает первые символы значения, **Then** система предлагает варианты из справочника тегов; при вводе нового значения тег создаётся и действует сразу (пост-модерация, FR-4).

## AC-3 (UC-3; FR-5, FR-6, FR-9)

- **Given** карточка с совпадением тега навыка с анкетой участника и карточка без совпадения, **When** формируется колода, **Then** карточка с совпадением идёт раньше; при равном совпадении порядок не фиксирован (FR-5).
- **Given** карточка с совпадением только по личному интересу и карточка с совпадением по навыку или проф. интересу, **When** формируется колода, **Then** вторая идёт раньше (FR-5, Q14).
- **Given** участник оценил карточку, **When** колода обновляется в течение 30 дней после оценки, **Then** эта карточка не показывается (FR-9).
- **Given** участник оценил карточку более 30 дней назад и других неоценённых карточек нет, **When** колода обновляется, **Then** эта карточка показывается повторно, оценка не сброшена (FR-9).
- **Given** все рекомендации исчерпаны (нет ни новых, ни допущенных к возврату карточек), **When** участник открывает колоду, **Then** показывается заглушка об исчерпании колоды (текст интерфейса — на английском, NFR-13), ошибок нет.
- **Given** участник оценил карточку, **When** находит того же участника в поиске, **Then** карточка показывается с меткой текущей оценки (FR-9, FR-12).

## AC-4 (UC-4; FR-7, FR-8, FR-14, NFR-12)

- **Given** участник A оценил B «интересно», а B не оценил A, **When** B открывает карточку A или запрашивает её через API, **Then** контакт A не раскрыт B.
- **Given** участник A оценил B «интересно» без взаимности, **When** B использует приложение или запрашивает API, **Then** факт оценки A не раскрыт B ни в интерфейсе, ни в ответе API (FR-7, Q19).
- **Given** взаимные оценки «интересно», **When** проходит ≤ 1 мин, **Then** оба получили от бота сообщение с Telegram-контактом друг друга (приёмка — после спайка `tg://user?id`, [docs/spikes/tg-user-link.md](../spikes/tg-user-link.md)).
- **Given** матч создан, **When** участник повторно открывает раздел «Матчи» в Mini App, **Then** контакт второй стороны доступен (FR-8).
- **Given** матч создан, но уведомление бота не доставлено (бот заблокирован), **When** участник открывает раздел «Матчи», **Then** контакт второй стороны доступен (FR-8).
- **Given** матч создан, **When** участник снимает свою оценку «интересно», **Then** раскрытый контакт сохраняется (FR-8, FR-12).

## AC-5 (UC-5; FR-10, FR-11, FR-12, NFR-2)

- **Given** 100 анкет, из них 10 с тегом `Kafka` (алиасы `kafka`, `Кафка`) и 90 без него, **When** запрос «разобраться с кафкой», **Then** первые 10 результатов — анкеты с тегом `Kafka`, и они идут выше анкет без тега; ответ ≤ 5 с (NFR-2).
- **Given** анкета с проектом, содержащим слово «миграция», **When** запрос «миграция», **Then** анкета присутствует в результатах (поиск по проектам, FR-10).
- **Given** анкета с профессиональным интересом «Kafka» и анкета с навыком «Kafka», **When** запрос «кафка», **Then** анкета с навыком выше анкеты с интересом (приоритет полей, FR-10).
- **Given** анкета с личным интересом «Kafka» и анкета с профессиональным интересом «Kafka», **When** запрос «кафка», **Then** анкета с профессиональным интересом выше (приоритет полей, FR-10, Q14).
- **Given** результаты поиска, **When** применён фильтр «offline + Москва», **Then** остаются только анкеты с локацией Москва и форматом offline/any (FR-11).
- **Given** участник оценил карточку из поиска «интересно», **When** вторая сторона также оценивает его «интересно», **Then** срабатывает UC-4 (FR-12, FR-7).
- **Given** запрос без совпадений и применённые фильтры, **When** поиск выполнен, **Then** показывается пустой результат с предложением смягчить фильтры (FR-10, UC-5 3а), ошибок нет.
- **Given** участник выполняет поиск, совпадающий с его собственной анкетой, **When** результаты возвращены, **Then** его карточка в результатах отсутствует (FR-10).
- **Given** участник, **When** отправляет пустой запрос или запрос длиннее 256 символов, **Then** поиск не выполняется, показано сообщение (FR-10).
- **Given** участник оценил карточку «интересно» без взаимности, **When** он меняет оценку на «не интересно», **Then** оценка обновлена, матч не создаётся (FR-12).
- **Given** 15 анкет, релевантных запросу, **When** поиск выполнен, **Then** первая страница содержит 10 карточек, остальные 5 доступны следующей страницей (FR-10).

## AC-6 (UC-6; FR-13, FR-15, NFR-7, NFR-9, NFR-12)

- **Given** запрос к API без валидного Telegram `initData`, **When** запрос выполняется, **Then** ответ 401.
- **Given** не-модератор вызывает функцию управления допуском, ссылок-приглашений или отзыва тегов (FR-15), **When** запрос выполняется, **Then** ответ 403.
- **Given** участник создал новый тег и использует его в анкете, **When** модератор отзывает тег, **Then** тег удалён из справочника и из анкет участников, автор тега получает уведомление бота ≤ 1 мин (FR-4, FR-15, NFR-12).
- **Given** отзываемый тег — единственный навык участника X, **When** модератор отзывает тег, **Then** карточка X исключена из поиска и колод, X получает уведомление бота ≤ 1 мин; после добавления навыка карточка возвращается (FR-2, FR-4, NFR-12).
- **Given** заявка кандидата, **When** модератор одобряет её, **Then** кандидат получает уведомление бота ≤ 1 мин (NFR-12) и доступ к онбордингу (UC-1).
- **Given** заявка кандидата, **When** модератор отклоняет её, **Then** кандидат получает уведомление бота ≤ 1 мин (NFR-12), онбординг недоступен, повторная подача разрешена (FR-13).
- **Given** ссылка-приглашение, по которой уже завершён онбординг, **When** другой кандидат переходит по ней, **Then** доступ отклонён (FR-13).

## AC-7 (нефункциональные требования; NFR-1, NFR-3…NFR-6, NFR-8, NFR-10, NFR-11, NFR-13)

- **NFR-1.** **Given** устройство с сетью 4G, **When** участник открывает Mini App, **Then** первичная загрузка завершается ≤ 3 с (замер на реальном устройстве, p95 по 10 запускам).
- **NFR-3.** **Given** участник в колоде карточек, **When** он оценивает карточку, **Then** следующая карточка отрисована ≤ 1 с в p95.
- **NFR-4.** **Given** нагрузочный тест 50 одновременных сессий на базе 1 000 анкет, **When** выполняются основные операции (колода, оценка карточки, поиск), **Then** ответы API укладываются в NFR-2/NFR-3.
- **NFR-5.** **Given** участник, **When** он пытается добавить 31-й навык, 21-й проект или 31-й интерес, **Then** система отклоняет ввод с понятным сообщением о лимите.
- **NFR-6.** **Given** эксплуатация за месяц, **When** подсчитывается суммарное время недоступности по журналу инцидентов (мониторинг), **Then** оно ≤ 7,2 ч (1% от 720 ч календарного месяца, доступность ≥ 99%).
- **NFR-8.** **Given** участник без матча с X, **When** он запрашивает карточку X через API, **Then** ответ не содержит ни username, ни user id X, ни скрытых до матча полей (`first_name`, `last_name`, аватар — FR-14); проверка сырого ответа API.
- **NFR-10.** **Given** юрисдикция MVP — без явных требований (Q3), **When** проводится аудит документации, **Then** задокументированы: место хранения ПДн, политика хранения, процедура удаления анкеты по запросу (FR-17), журнал раскрытия контактов и решений модератора со сроком хранения 1 год (NFR-10).
- **NFR-11.** **Given** актуальные клиенты Telegram на iOS, Android и Desktop, **When** участник проходит UC-1…UC-5, **Then** все сценарии работоспособны на каждой платформе (ручной чек-лист).
- **NFR-13.** **Given** участник открывает Mini App, **When** интерфейс отображается, **Then** все элементы интерфейса на английском; анкеты на русском и английском отображаются и находятся поиском (FR-10, Q23).

## AC-8 (UC-7; FR-17)

- **Given** участник с матчами, **When** удаляет анкету и подтверждает, **Then** анкета, оценки и матчи удалены; в списках матчей второй стороны контакт помечен недоступным.
- **Given** удалённая анкета, **When** выполняется поиск, **Then** карточка удалённого участника в результатах не появляется.
