# Спайк T-3. Тестовый корпус запросов для AC-5 (ранжирование поиска)

Задача 3.1.2. Корпус формирует команда (Q-3.2). Правила ранжирования — ADR-003:
точный тег (уровень 1: леммы термов ⊆ lexemes алиаса; внутри — skill > professional_interest > personal_interest)
выше совпадения по тексту (уровень 2: fts_doc, веса навыки A > проекты B > проф. интересы C > личные D).
Исполнение: `internal/httpapi/search_corpus_test.go` (интеграционный тест на реальной БД).

## Кейсы

| # | Запрос | Ожидание |
|---|---|---|
| C1 | `Kafka` | P1 первый (тег-навык выше всех); P2/P3/P4 в выдаче ниже P1 |
| C2 | `разобраться с кафкой` | P1 первый (лемма «кафк» = алиас, уровень 1) — флагманский AC-5; P5/P6 вне выдачи |
| C3 | `кафкой` | P1 первый (стемминг терма) |
| C4 | `Go` | P5 первый; P1/P2 вне выдачи (нет совпадений) |
| C5 | `no-such-term` | пустая выдача, 200, без ошибки (FR-10) |
| C6 | `Kafka` + фильтр location=другой город | пустая выдача + filters_applied=true (FR-10/FR-11) |
| C7 | порядок внутри уровня 1: P1 (skill) выше P3 (prof) выше P4 (personal) при совпадении одного терма по алиасам разного kind | P1 > P3 > P4 |

## Известное ограничение (D-1.1, открыт)

AND-семантика `websearch_to_tsquery`: «разобраться с кафкой» на уровне 2 требует всех термов —
анкета с тегом Kafka, но без слова «разобраться» в тексте, находится только через уровень 1 (алиасы).
Это покрывает флагманский кейс; OR-фолбэк — открытый вопрос D-1.1.
